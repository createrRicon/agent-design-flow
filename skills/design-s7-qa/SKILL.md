# S7 设计验收

## 定位
- 输入：handoff.md（验收点）、STATUS.md「留给验收的交互验收点」（原型阶段整理；旧需求里叫「留给 S6 的交互验收点」）、定稿 Figma、测试环境地址
- 输出：`qa-checklist.md`（检查表 + 问题清单）
- 设计师在测试环境亲自点一遍，AI 负责生成清单、整理结果、写问题单

## 流程
1. 从 handoff.md 抽出所有验收点，并入 STATUS.md 里的交互验收点（重复的合并），按画面分组，生成检查表。每条写清楚**怎么操作才能触发**（比如"勾选一个签名未检出的记录"），不要只写期望结果
2. 补充通用检查项（每个需求都要查）：
   - 组件变体和尺寸与 Figma 一致
   - 颜色、字号、间距没有明显偏差
   - 空状态、加载状态、错误状态都存在
   - 文案与 handoff 一致
   - 无权限角色看不到操作入口
   - Storybook `START_HERE.md` 的硬规则：每个操作区最多 1 个 Primary、按钮 Title Case、禁用按钮有原因说明、跳转用链接不用按钮
   - 提示方式和文案符合 `FEEDBACK.md`、`CONFIRM_DIALOG.md`：确认弹窗是 No / Yes，配置、提交类表单弹窗是 Cancel / Confirm；一次操作只弹一条提示；表单报错显示在字段下方
3. 设计师检查后，用最省事的方式回报结果，比如"1–8 过，9 不过：按钮没隐藏"，或者直接贴截图。AI 负责写回检查表
4. 不通过的项整理成问题清单，每条写：
   - 画面 · 现象（附截图）· 期望（引用验收点或 Figma frame）· 严重程度（阻塞上线 / 上线前修 / 可以后续优化）
5. 问题清单单独输出一段，设计师可以直接转发给前端

## 可选：浏览器辅助
如果会话里有浏览器工具，且设计师提供了测试环境地址：AI 可以按检查表打开页面、截图，与 Figma frame 并排对比，先筛一遍明显的视觉偏差。
- 登录必须由设计师自己完成，AI 不输入任何账号密码
- 交互类验收点（点击后的行为）仍以设计师亲自操作的结果为准

## qa-checklist.md 格式
```
## <画面名>
- [ ] V-01 <操作步骤> → <期望结果>（来源：D-x 验收点）
...
## 问题清单
| # | 画面 | 现象 | 期望 | 严重程度 |
```
