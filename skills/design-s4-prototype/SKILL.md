# S4 交互原型

## 定位
- 输入：decisions.md（规则 + S3 选定的呈现）+ S3 方案画布链接
- 输出：一个可交互原型；STATUS.md 里新增的交互验收点
- 下游：S5 只把确认过的原型落到 Figma
- 分工：AI 做原型；交互顺不顺由设计师亲自点过后决定
- 开工前检查 decisions.md：还有呈现分歧没"选定"，先回 S3
- 开工前先读 Storybook 交互与文案规范（路径见 `Design-Pipeline/PIPELINE.md`「全局规范位置」），重点是 `FEEDBACK.md` 和 `CONFIRM_DIALOG.md`

## 流程
1. 默认只做选定方案。一个需求一个原型，多个页面用页内切换。设计师要在原型里比较方案时，按下方「方案对比」做，仍然是同一个原型。
2. 形式二选一：
   - 默认：单文件 HTML，发布为 claude.ai Artifact，方便直接发给评审
   - 改版且要大量复用现有页面样式时：本地 `prototype/` 目录，`_source/*.src.html` 写源码，`build.ps1` 生成，`export.ps1` 导出离线版（参考 `Design-Projects/2026-09-container-list/prototype`）
3. 要能点的：decisions.md 每条规则的主流程，加上边界情况（空、失败、权限、翻页 / 筛选 / 切换后状态）。业务事实没定的按推荐做，原型里不标，记在 STATUS.md 待确认。
4. 演示控制：起始状态、模拟异常（上传失败、后端校验失败等）、规则命中记录。放进一个默认收起的控制台，用开关打开，不挡产品界面。
5. 不放验收清单（"点到就亮"之类）。能在原型里点出来的验收点，写进 STATUS.md「留给验收的交互验收点」。
6. 界面文案用英文，按 Storybook 规范写：按钮和弹窗标题 Title Case；确认弹窗"标题说操作 + 正文一句是非问句 + No / Yes"，优先套 CONFIRM_DIALOG.md 的标准文案库；配置类、提交类表单弹窗用 Cancel / Confirm；成功提示"对象 + 过去分词"，失败 "Couldn't ..."，表单报错 "Please enter / select ..."。颜色、字号、间距取 团队的设计系统 的值，不另起一套。Detail 页的外壳按 `Design-Pipeline/detail-page-template.md`。
7. 交给设计师亲自体验。体验或评审中要改时：
   - 规则变了：回写 decisions.md，状态改"原型后改"并写原因
   - 只是样子变了：直接改原型；如果推翻了 S3 的选定，回写 decisions.md 的"呈现"段
   - 评审意见走 design-review

关卡：设计师体验后确认（"原型 OK"），评审意见已处理，才进入 S5。

## 方案对比（原型内）
什么时候用：画布上看不出差别、要亲手点才能判断的呈现分歧（入口位置、操作顺序、反馈方式等），或设计师要求"再做一个方案在原型里比"。纯视觉差异回 S3 画布比较。

1. **页面结构先对齐模板**：Detail 页按 `Design-Pipeline/detail-page-template.md` 搭外壳（240 侧栏、56 顶栏、内容区四边 16、信息卡右上角放主操作、详情卡 Tab + Section）。**Section 标题行右侧只放 CTA，状态和回显放内容区**；方案若违反这条，先跟设计师确认再做。方案之间只改分歧的那一处，外壳、数据、文案都不动，否则比较不出结论。
2. **顶部方案切换条**：页面最上方一条深色条（sticky，不属于产品界面），左侧写"Prototype · 方案对比"和要比较的问题（如"图片上传入口的位置"），中间是分段按钮 `A 方案短名` / `B 方案短名`，右侧提示快捷键 `1` / `2`。
3. **切换不丢状态**：所有方案读写同一份数据。切换只换渲染，用户的操作进度（已传的图、展开的分组、错误数）保留，这样同一个场景可以来回对比。
4. **每个方案覆盖全部状态**：空、缺失、已完成、只读、报错等，每个方案都要能点到；某个方案天然不需要某一步（例如入口在标题栏时不用展开分组），在规则命中记录里写明。
5. **默认显示当前推荐**：首次打开显示 decisions.md 里当前选定（或推荐）的方案；浏览器记住上次选的方案（localStorage，读写都包 try/catch）。
6. **记录到控制台**：切换方案、以及走了方案特有的路径，都写进"规则命中记录"，带方案字母。
7. **比较完要收口**：设计师选定后，删掉落选方案和切换条，把选定结果和理由回写 decisions.md 的"呈现"段（写日期，注明"原型内比较后选定"），再进 S5。切换条不进 Figma，也不进交付。

## 报告
原型链接；覆盖了哪些决策和边界情况；哪些地方因业务未定按推荐做了；新增了哪些交互验收点；有方案对比时，列出每个方案改了哪一处、各自的取舍。
